# MCP-тули

Усі тули оголошені в `task_manager.py` (`@mcp.tool`), разом **23**. Помилки бізнес-правил повертаються
текстом із префіксом `⚠️` (для `format="json"` — `{"error": "..."}`), а не винятком. Формат задачі й
правила переходів — [format.md](format.md).

Спільні правила параметрів:

- `edit_task`: порожнє значення = «не чіпати»; `none` (також `-`, `—`) = «очистити поле». Виняток —
  `title`: його не можна очистити.
- Списки (`domains`, `links`) — через кому або пробіл; провідний `#` у тегах відкидається.
- `status` = `backlog|todo|blockers|in_progress|in_review|testing|done`; `priority` = `asap|high|low`;
  `energy` = `S|M|L`; `deadline` = `РРРР-ММ-ДД`; `project` = слаг проєкту або `global`.
- `agent` у `elf_*` = `claude|codex`.

## Задачі

| Тул | Параметри | Що робить |
|---|---|---|
| `list_tasks` | `status`, `project`, `priority`, `domain`, `query`, `limit=50`, `format` | Короткі рядки задач. Без `status` задачі `done` не показуються (внизу — скільки приховано); `status=done` — лише вони. `query` — підрядок у заголовку чи тексті. `status=todo` — у ручному порядку колонки To Do. `limit` обмежується діапазоном 1–500. |
| `get_task` | `id`, `format` | Одна задача повністю: текст, пріоритет, дедлайн, енергія, теги, проєкт, звʼязки, план. |
| `board` | — | Кількість задач по колонках, `in progress` у вигляді `N/ліміт` (з позначкою перевищення), і список задач у `in_progress`, `in_review`, `testing`. |
| `add_task` | `text`, `title`, `project`, `priority`, `deadline`, `energy`, `domains`, `links`, `plan` | Нова задача; `text` і `title` обовʼязкові; завжди потрапляє в `backlog`; `text` — один рядок, багаторядковий опис — у `plan`. |
| `move_task` | `id`, `status` | Перемістити за матрицею переходів із WIP-гардом; `backlog → todo` через MCP заборонено. |
| `set_priority` | `id`, `priority` | Змінити пріоритет (`none` — зняти). |
| `set_deadline` | `id`, `deadline` | Змінити дедлайн (`none` — зняти). |
| `comment_task` | `id`, `text` | Дописати рядок `РРРР-ММ-ДД текст` у розділ `## Elf` плану (розділу нема — створюється). До 4000 символів, наступні рядки йдуть із відступом. Статус і поля не змінює; запис потрапляє в журнал. |
| `edit_task` | `id`, `text`, `title`, `status`, `priority`, `deadline`, `energy`, `domains`, `links`, `project`, `plan` | Змінити будь-які поля за один виклик. Зміна `project` фізично переносить задачу між файлами. Зміна `status` підлягає тим самим правилам, що й `move_task`. |
| `delete_task` | `id` | Видалити задачу (і файл її плану) без можливості відновлення; повний знімок лишається в журналі. |

### Вивід у JSON

`list_tasks` і `get_task` приймають `format="json"` (порожньо — текст; інше значення — помилка):

- `list_tasks` → `{"tasks": [{id, title, text, status, priority, deadline, energy, domains, project, links}],
  "more": N, "hidden_done": N}`; `project` — слаг або `global`; `title` без заголовка дорівнює `text`.
- `get_task` → ті самі поля задачі плюс `"plan"` (`null`, якщо плану нема).
- Помилка — `{"error": "..."}`.

## Робочий цикл Elf (`elf_*`)

Тули для автоматичного агента-виконавця. Стан циклу (лічильник невдач, посилання на PR, результат CI)
лежить в `elf-state.json`, а не в рядку задачі. Службові теги задачі: `to-agent` (у черзі для агента),
`blocked`, `to-admin` (потрібна людина), `dev` (задача з кодом і PR). Тег агента — `claude` або `codex`;
задача без тегів агентів належить `claude`.

Поріг невдач — **3**: третя невдача підряд (повернення, червоний CI, повернення з рев'ю) замість
звичайного повернення блокує задачу так само, як `elf_block`; лічильник після блокування скидається в 0.
Кожна дія дописує рядок у розділ `## Elf` плану й пишеться в журнал.

| Тул | Параметри | Що робить |
|---|---|---|
| `elf_claim` | `agent` | Бере верхню підходящу задачу To Do → `in_progress`. Підходить задача з тегом `to-agent`, без `blocked`, з тегом агента. Відповідь — id, заголовок, текст, лічильник невдач, план; черга порожня — `no tasks`. |
| `elf_release` | `id`, `reason`, `agent` | Повертає задачу з `in_progress` нагору To Do, невдач +1. |
| `elf_block` | `id`, `reason`, `agent` | З `in_progress` або `in_review`: створює задачу в `blockers` (теги `to-admin` + агент, той самий проєкт); оригінал стає першою в To Do без `to-agent`, з тегами `blocked` + агент; лічильник невдач — 0. |
| `elf_submit` | `id`, `agent`, `pr=""` | `in_progress` → `in_review` (задача з тегом `dev`; `pr` обовʼязковий) або → `testing` (без `dev`). |
| `elf_ci` | `id`, `result` | Для задачі в `in_review`: `green` — запамʼятати; `red` — як невдача (нагору To Do, невдач +1). |
| `elf_review_next` | `agent` | Лише читає: задачі в `in_review` із зеленим CI для агента (id, заголовок, PR), без тега `to-admin`. Нічого нема — `nothing to review`. |
| `elf_merged` | `id` | `in_review` → `testing`. |
| `elf_return` | `id`, `comment`, `agent` | Рев'юер повертає задачу з `in_review` нагору To Do, невдач +1, результат CI скидається. |
| `elf_escalate` | `id`, `reason`, `agent` | Задача лишається в `in_review`, отримує тег `to-admin` і зникає з `elf_review_next`; лічильник невдач не змінюється. |
| `elf_audit` | `week`, `prs` | Створює в `backlog` задачу «Аудит Elf тижня `<week>`» (проєкт `elf`, тег `to-admin`, список PR у плані). `week` — `РРРР-Wнн` (01–53); `prs` — 1–50 URL виду `https://github.com/<owner>/<repo>/pull/<n>`, дублікати зливаються. Задача цього тижня вже є (будь-який статус) — повертає її id, нічого не змінює. |

Причина (`reason`, `comment`) — непорожній текст; переноси рядків згортаються в пробіли.

## Анотації

Анотації тулів читають клієнти (напр. ChatGPT), щоб вирішити, що питати на підтвердження. Усі тули мають
`openWorldHint=false`.

| Група | Тули |
|---|---|
| read-only | `board`, `list_tasks`, `get_task`, `history`, `list_projects`, `elf_review_next` |
| запис, не ідемпотентний | `add_task`, `comment_task`, `create_project`, `elf_claim`, `elf_release`, `elf_block`, `elf_submit`, `elf_ci`, `elf_merged`, `elf_return`, `elf_escalate`, `elf_audit` |
| запис, ідемпотентний (повтор із тим самим значенням нічого не змінює) | `move_task`, `set_priority`, `set_deadline` |
| деструктивні | `edit_task` (очищення полів, перенос між файлами), `delete_task` |

## Права токена `elf`

Окрема змінна `TASKS_ELF_TOKEN` вмикає на bearer-інстансі другий, обмежений токен для раннера Elf
(порожньо або не задано — вимкнено; див. [config.md](config.md)). Запит із цим токеном:

- приймається лише з loopback (`127.0.0.1`, `::1`); раннер має ходити на bearer-порт напряму: за
  reverse-проксі на тому ж хості перевірка loopback нічого не дає;
- приймається лише на MCP-шляху; дашборд і `/api/*` → 403;
- дозволені виклики тулів: усі `elf_*`, `list_tasks`, `get_task`, `board`, `move_task`, `comment_task`, і
  `edit_task` лише з аргументами `id` та/або `domains`; будь-який інший тул чи аргумент → 403;
- зміни під ним пишуться в журнал із клієнтом `elf`.

На OAuth-інстансі цей токен не діє.
