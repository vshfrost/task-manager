# Веб-дашборд і REST API

Дашборд — канбан і календар над тим самим `PlannerStore`, що й MCP-тули. Код — `web_ui.py`. Сторінка —
один самодостатній HTML (без збірки, npm і зовнішніх CDN), доступна за шляхом `/task-manager`. Старий шлях
`/ui` віддає `302` на нову адресу. Дані задач потрапляють у DOM лише через `textContent`.

## Можливості сторінки

- **Канбан** — 7 колонок у порядку статусів (`backlog`, `to do`, `blockers`, `in progress`, `in review`,
  `testing`, `done`); перетягування картки між колонками змінює статус за [матрицею переходів](format.md).
  Скидання картки на місце в колонці To Do ставить її на цю позицію. Лічильник `in progress` показує
  ліміт.
- **Календар** — задачі за дедлайнами; показується заголовок задачі, а не повний текст.
- **Форма задачі** — заголовок (≤ 50 символів, обовʼязковий; поки поле порожнє, форма пропонує чернетку з
  тексту), текст, план (markdown), проєкт (селект наявних), статус (лише при редагуванні: нова задача
  завжди йде в `backlog`), пріоритет, дедлайн, енергія, теги (обрати наявний або дописати новий і
  натиснути Enter), звʼязки (лише вибір із наявних).
- **Новий проєкт** — кнопка 📁: слаг, назва, репозиторій (`POST /api/project`).
- **Кольори тегів** — кнопка 🎨: колірпікер для кожного тега, «✕» знімає колір.
- **Шаблони** — селект «Шаблон…» створює типову задачу в один клік (джерело — [шаблони](format.md)).
- **Історія** змін задачі показується в діалозі редагування (`GET /api/history`).
- Перенос у `done` показує повноекранне святкове конфеті; при `prefers-reduced-motion` — лише плашка.

## REST API

Усі маршрути, крім `/ui`, виконуються з джерелом змін `web` у [журналі](history.md). Тіло POST-запитів —
JSON-обʼєкт (інакше `400`). Помилка — `{"error": "<текст>"}` зі статусом `400` (`404` для
`GET /api/task`, якщо задачі нема).

| Метод і шлях | Що робить |
|---|---|
| `GET /task-manager` | сторінка дашборда |
| `GET /ui` | `302` на `/task-manager` |
| `GET /api/tasks` | задачі й довідники (нижче). Фільтри в query: `status`, `project`, `priority`, `domain` |
| `GET /api/task?id=<id>` | одна задача з планом: `{"task": {…, "plan": "…"}}` (ключ `plan` є, лише якщо план є) |
| `GET /api/tag-colors` | `{"tag_colors": {...}}` |
| `POST /api/tag-color` | `{"tag": "<тег>", "color": "#RRGGBB"}`; `"color": null` знімає колір; відповідь — усі кольори |
| `GET /api/projects` | `{"projects": [{slug, name, repo}]}` |
| `POST /api/project` | `{"slug", "name", "repo"}` → `{"project": {...}}` |
| `POST /api/task/add` | поля: `text`, `title`, `project`, `priority`, `deadline`, `energy`, `domains`, `links`, `plan` → `{"task": {...}}` |
| `POST /api/task/edit` | `id` і будь-які з полів `add` плюс `status` і `position` → `{"task": {...}}` |
| `POST /api/task/delete` | `{"id": "<id>"}` → `{"task": {...}}` (знімок видаленої) |
| `GET /api/history` | `{"records": [...]}`; query: `id` (опційно), `limit` (за замовчуванням 30, обмежується 1–200) |

`GET /api/tasks` повертає `tasks` (поля `id`, `status`, `text`, `domains`, `priority`, `deadline`, `energy`,
`links`, `title`, `file`; без плану), `projects`, `domains`, `links` (довідники з наявних даних),
`templates`, `tag_colors`, `title_max` (50) і `wip_limit`.

Особливості `POST /api/task/edit`:

- Відсутнє поле або `""` — не чіпати; `none` (також `-`, `—`) — очистити; `title` очистити не можна.
  `domains` і `links` — список або рядок через кому/пробіл.
- Зміна `status` підлягає матриці переходів і WIP-ліміту; **`backlog` → `todo` тут дозволений** (через MCP —
  заборонений).
- `position` — 1-based місце в колонці To Do; приймається лише разом зі `status: "todo"` або для задачі,
  що вже в To Do; недійсне значення → `400`, нічого не пишеться.
- `plan`: рядок записується як є; `""` або `none` прибирає план.

## Безпека

Дашборд і `/api/*` **не мають власної авторизації**. Захист — виключно мережевий: вони реєструються
**лише на bearer-інстансі** (і в stdio-режимі), який слід відкривати лише з довіреної мережі (приватна
мережа, фаєрвол). Bearer-мідлварь вимагає токен тільки на MCP-шляху, тож `/task-manager` і `/api/*`
браузер відкриває без заголовків.

**Не реєструвати дашборд на OAuth-інстансі:** він стоїть за публічним reverse-проксі, і всі його маршрути
стають публічними — дашборд без пароля опинився б в інтернеті. Не виставляти за публічний проксі й
bearer-інстанс. Код має два запобіжники:

1. умова `if not _OAUTH` у `task_manager.py` — на OAuth-інстансі `web_ui` навіть не імпортується;
2. `assert not is_oauth` у `web_ui.register()` — виклик із `is_oauth=True` падає (є тест у
   `tests/test_store.py`).

Запити з токеном `elf` до дашборда й `/api/*` дістають `403` ([tools.md](tools.md#права-токена-elf)).
